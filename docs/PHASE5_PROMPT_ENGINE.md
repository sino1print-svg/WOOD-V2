# Phase 5 Prompt Engine

The Prompt Engine composes deterministic Output A blank-sale prompts and Output B matching-preview edit prompts. It performs runtime validation before every public composition call and does not generate images, access networks or filesystems, persist data, or implement later phases.

Canonical section order is Global, Product, Season, Scene, Output. Official section ownership is internal. Descriptive fields cannot introduce official sibling sections or override mandatory constraints.

## Second corrective hardening

The public validation pipeline now performs structural text isolation and centralized cross-object relationship validation before trusted section composition. Resolved text cannot create sibling prompt sections or control blocks. Both Output B source hashes must match Output A content state, and Output A garment identity must match the selected product's canonical `type` field.

## Third corrective — resolved-text isolation

Prompt composition now uses a centralized closed-world resolved-data pipeline. Raw resolved descriptions are not interpolated by the composer. Field-specific descriptive clauses are canonicalized before trusted section construction; clauses outside the permitted descriptive model cannot reach prompt output. Optional custom notes are represented as deterministic opaque data.
